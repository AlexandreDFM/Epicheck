# Building APK Locally (Without EAS)

This guide explains how to build an APK for your EpiCheck app without using Expo Application Services (EAS).

## Prerequisites

✅ **Already Installed:**

- Java JDK 17 (OpenJDK)
- Android SDK
- Android platform-tools (adb)
- Android build-tools 36.0.0
- Android platform 36

## Build Options

### 1. Debug APK (Development Build)

Build a debug APK that can be installed on any Android device:

```bash
pnpm run build:android:debug
```

Or directly:

```bash
expo run:android --variant debug
```

**Output location:** `android/app/build/outputs/apk/debug/app-debug.apk`

```bash
cp android/app/build/outputs/apk/debug/app-debug.apk ./epicheck-debug.apk
```

### 2. Release APK (Production Build)

Build a release APK for distribution:

```bash
pnpm run build:apk
```

Or:

```bash
pnpm run build:android:release
```

**Output location:** `android/app/build/outputs/apk/release/app-release.apk`

```bash
cp android/app/build/outputs/apk/release/app-release.apk ./epicheck-release.apk
```

## First Time Setup

If the `android` folder doesn't exist yet, generate it first:

```bash
pnpm exec expo prebuild --platform android
```

This creates the native Android project with all necessary configurations.

## Signing the Release APK (Production)

`android/` is generated by `expo prebuild`, so the signing config is not edited by hand: a config plugin in `app.config.ts` adds a `release` signing config that reads the key from **environment variables**. Without them, release builds are signed with the public debug key (fine for a local test, not for distribution).

| Variable                    | Value                                                |
| --------------------------- | ---------------------------------------------------- |
| `ANDROID_KEYSTORE_FILE`     | Absolute path to the keystore (`.jks` / `.keystore`) |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password                                    |
| `ANDROID_KEY_ALIAS`         | Key alias                                            |
| `ANDROID_KEY_PASSWORD`      | Key password                                         |

The keystore stays outside the repository (`*.jks`, `*.keystore`, `*.p12` are ignored). Keep a backup of it and of its passwords in a password manager: the same key is needed to publish any later update.

> **Play Store:** with Play App Signing (the default), the key you hold is the **upload key**; Google re-signs the app for Play users. An APK signed with the upload key and an app installed from the Play Store therefore cannot update each other: uninstall one before installing the other.

### Local signed build

```bash
export ANDROID_KEYSTORE_FILE="$HOME/keys/epicheck-upload.jks"
export ANDROID_KEY_ALIAS=epicheck
read -rs ANDROID_KEYSTORE_PASSWORD && export ANDROID_KEYSTORE_PASSWORD
read -rs ANDROID_KEY_PASSWORD && export ANDROID_KEY_PASSWORD

pnpm exec expo prebuild --platform android
cd android && ./gradlew assembleRelease bundleRelease && cd ..
# APK: android/app/build/outputs/apk/release/app-release.apk
# AAB (Play Store): android/app/build/outputs/bundle/release/app-release.aab
```

Check the signature: `$ANDROID_HOME/build-tools/<version>/apksigner verify --print-certs android/app/build/outputs/apk/release/app-release.apk`.

### CI signed build (`.github/workflows/android.yaml`)

Store the key as repository secrets of `epitech-nice/EpiCheck` without displaying them:

```bash
R=epitech-nice/EpiCheck
base64 -i "$HOME/keys/epicheck-upload.jks" | tr -d '\n' | gh secret set ANDROID_KEYSTORE_BASE64 --repo $R
gh secret set ANDROID_KEYSTORE_PASSWORD --repo $R    # prompts for the value
gh secret set ANDROID_KEY_ALIAS --repo $R
gh secret set ANDROID_KEY_PASSWORD --repo $R
```

Then a `vX.Y.Z` tag (matching `package.json`) builds the signed APK and AAB and attaches them, with their SHA-256, to a GitHub release. A manual run (Actions → Android → Run workflow) builds them as an artifact only.

### New keystore (only if none exists)

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore epicheck-release.jks \
  -alias epicheck -keyalg RSA -keysize 2048 -validity 10000
```

## Installing the APK

### On Connected Device

```bash
adb install android/app/build/outputs/apk/release/app-release.apk
```

### Manual Installation

1. Copy the APK to your device
2. Open the APK file on your device
3. Allow installation from unknown sources if prompted
4. Install the app

## Build Options Comparison

| Build Type | Command                        | Use Case            | Size    | Performance |
| ---------- | ------------------------------ | ------------------- | ------- | ----------- |
| Debug      | `pnpm run build:android:debug` | Development/Testing | Larger  | Slower      |
| Release    | `pnpm run build:apk`           | Production          | Smaller | Optimized   |

## Troubleshooting

### Build Fails

1. Clean the build:

```bash
cd android && ./gradlew clean && cd ..
```

2. Rebuild:

```bash
pnpm run build:apk
```

### Missing Android Folder

Run prebuild:

```bash
pnpm exec expo prebuild --platform android
```

### Gradle Issues

Update Gradle wrapper:

```bash
cd android && ./gradlew wrapper --gradle-version=8.14.3 && cd ..
```

### Out of Memory

Edit `android/gradle.properties` and add:

```properties
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m
```

## Quick Build Commands

```bash
# Generate Android project (first time only)
pnpm exec expo prebuild --platform android

# Debug build
pnpm run build:android:debug

# Release build (unsigned)
pnpm run build:apk

# Install on device
adb install android/app/build/outputs/apk/release/app-release.apk

# Build and install in one command
expo run:android --variant release
```

## Notes

- Debug builds are automatically signed with a debug keystore
- Release builds are signed with the key given by the `ANDROID_KEYSTORE_*` variables (see above), otherwise with the debug key
- APK size will be ~30-50MB depending on assets and dependencies
- First build takes longer (5-10 minutes)
- Subsequent builds are faster (1-3 minutes)
